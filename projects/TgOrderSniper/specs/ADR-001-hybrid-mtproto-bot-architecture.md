# ADR-001: Использование гибридной архитектуры: MTProto Userbot для Event-Driven перехвата постов + Telegram Bot API для доставки карточек с inline-действиями

**Дата**: 2026-10-12  
**Статус**: Принято (Accepted)  
**Авторы / Участники**: Core Backend Team, Telegram Automation Architecture Lead  
**Технический домен**: Ingestion Pipeline, Messaging Dispatcher, Telegram Security & Compliance  

---

## Контекст и проблематика

Продукт **TgOrderSniper** предназначен для мониторинга сотен открытых и закрытых каналов и чатов фриланса, IT-заказов и проектных бирж в Telegram с целью оперативного оповещения команды исполнителей о новых коммерческих заказах. 

В сфере заказной разработки и фриланса скорость первого отклика (First Response Time) критически определяет конверсию: исполнители, откликнувшиеся в течение первых 30–60 секунд после публикации поста, получают до 80% всех контрактов.

При проектировании архитектуры возникли ключевые инженерные вызовы:
1. **Ограничения Telegram Bot API на чтение**: Официальный Telegram-бот не может читать сообщения в публичных или закрытых чатах, если он не добавлен туда администратором с явными правами чтения или если в группе отключен режим конфиденциальности (Privacy Mode). Мониторить чужие группы исключительно ботом технически невозможно.
2. **Риски бана и ограничений аккаунтов (Spam / FloodWait)**: Использование обычных user-аккаунтов (Userbot) для рассылки сообщений и активных действий в группах часто приводит к ограничениям `SpamBlock`, снижению лимитов и блокировке сессий.
3. **Требования к UX доставки**: Доставка заказа команде должна содержать кликабельные интерактивные кнопки (`InlineKeyboardButton` типа `url`), ведущие прямо на оригинальный пост и в диалог с заказчиком. Полноценная поддержка inline-кнопок гарантируется Telegram Bot API, тогда как для user-аккаунтов создание inline-клавиатур ограничено или недоступно обычным сообщениям.
4. **Задержка доставки (Latency)**: Традиционный опрос (Polling) создает задержки от десятков секунд до минут и генерирует огромный паразитный трафик.

## Рассмотренные альтернативы

### Альтернатива 1: Только Telegram Bot API (Long Polling / Webhooks)
- **Суть**: Использовать только официального Telegram-бота для всех операций.
- **Преимущества**: 
  - Официальный API, нулевой риск бана.
  - Поддержка inline-клавиатур и богатого HTML/Markdown форматирования.
- **Недостатки**:
  - **Блокирующий фактор**: Бот не видит сообщения в группах, где он не является администратором, и не может подписаться на произвольные чужие каналы.
- **Вердикт**: **Отклонено** как функционально неприменимое для мониторинга сторонних каналов.

---

### Альтернатива 2: Только MTProto Userbot (Telethon / Pyrogram на прием и отправку)
- **Суть**: Использовать сессию реального пользователя Telegram для прослушивания каналов и отправки сообщений в целевой рабочий чат.
- **Преимущества**:
  - Доступ ко всем публичным и приватным чатам, где состоит пользователь.
  - Мгновенные push-уведомления через MTProto TCP соединение.
- **Недостатки**:
  - Обычные пользователи не могут прикреплять inline-кнопки (`InlineKeyboardMarkup`) к своим сообщениям без привлечения inline-ботов.
  - Высокий риск ограничений Telegram Anti-Spam при частых отправках сообщений с одного пользовательского аккаунта.
  - Нарушение принципа наименьших привилегий (аккаунт выполняет и чтение, и активную отправку).
- **Вердикт**: **Отклонено** из-за ограничений UX (отсутствие нативных inline-кнопок) и риска компрометации userbot-сессии.

---

### Альтернатива 3: Web Scraping Telegram Web (Playwright / Puppeteer / Beautiful Soup)
- **Суть**: Запуск браузерной автоматизации или парсинга публичных web-страниц `t.me/s/<channel>`.
- **Преимущества**:
  - Не требуется авторизация по номеру телефона для ряда публичных каналов.
- **Недостатки**:
  - Не работает для закрытых групп и супергрупп.
  - Задержка обновления web-зеркал достигает нескольких минут (неприемлемо для сниппера заказов).
  - Колоссальное потребление памяти (500MB–1GB RAM на инстанс Chromium).
  - Блокировки Cloudflare и капчи при частом обновлении страниц.
- **Вердикт**: **Отклонено**.

---

### Альтернатива 4: Гибридная архитектура (MTProto Listener + Telegram Bot API Dispatcher) — ВЫБРАНО
- **Суть**: 
  - **Userbot (Telethon MTProto)**: Работает исключительно в режиме **Event-Driven Read-Only Listener**. Поддерживает постоянное TCP-соединение с дата-центрами Telegram и мгновенно получает push-события `events.NewMessage`. Не отправляет никаких сообщений, не совершает исходящих запросов в каналы.
  - **Telegram Bot API (httpx AsyncClient)**: Служит выделенным **диспетчером доставки**. Получает нормализованный заказ от движка фильтрации и отправляет красивую HTML-карточку с `InlineKeyboardMarkup` в закрытую группу команды через официальный эндпоинт `https://api.telegram.org/bot<token>/sendMessage`.

---

## Архитектурное решение

Принято решение реализовать **гибридную архитектуру (Hybrid MTProto + Bot API)**:

1. **Компонент Ingestion (`TelegramListener`)**:
   - Построен на базе библиотеки `Telethon` (MTProto 2.0).
   - Поддерживает сессии SQLite (`.session`) и stateless `StringSession`.
   - Зарегистрирован на обработку `events.NewMessage(chats=...)`.
   - Нагрузка на MTProto сведена исключительно к пассивному приему push-событий (0 исходящих запросов, нулевой риск FloodWait).
2. **Компонент In-Memory Guard (`MessageDedup`)**:
   - Двойная дедупликация: по составному ключу `chat_id:message_id` и SHA-256 хешу нормализованного текста (отлов кросс-постов между несколькими биржами).
3. **Компонент Delivery (`TelegramBotDispatcher`)**:
   - Построен на прямых асинхронных HTTP-вызовах через `httpx.AsyncClient`.
   - Формирует интерактивные кнопки с deep-links (`https://t.me/...` и `tg://user?id=...`).
   - Автоматически обрабатывает Rate Limiting (HTTP 429) с учетом заголовка `retry_after` и выполняет экспоненциальный retry при сетевых сбоях.

## Последствия и преимущества

### Положительные последствия:
1. **0 секунд задержки (Event-Driven 0s Latency)**:
   - Сообщения перехватываются мгновенно по TCP-сокету в момент их генерации Telegram MTProto сервером, без ожидания интервала опроса.
2. **Абсолютная антибан-защита пользовательского аккаунта**:
   - Userbot работает в режиме 100% Read-Only. Для серверов Telegram поведение аккаунта неотличимо от пассивного чтения переписки обычным пользователем в официальном клиенте.
   - Никаких действий спама, пересылок или публикаций от имени пользователя не производится.
3. **Богатый UX и интерактивность**:
   - Использование Telegram Bot API позволяет крепить полноразмерные inline-кнопки прямо под сообщением.
   - Возможность форматирования HTML с тегами `<b>`, `<code>`, `<a>` и ссылками на профили пользователей.
4. **Масштабируемость и простота деплоя**:
   - Поддержка `StringSession` позволяет хранить сессионный ключ в переменной окружения `.env` и запускать систему в Docker/Kubernetes без привязки к дисковым файлам.

### Ограничения и компромиссы:
- Требуется наличие активного Telegram-аккаунта (для генерации сессии MTProto) и зарегистрированного бота в `@BotFather`.
- В целевой группе команды бот должен обладать правами на отправку сообщений (права администратора не обязательны, но рекомендуются).
