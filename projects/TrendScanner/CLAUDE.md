# TrendScanner — Standing Directives & Architecture Rules

## 1. Паттерн Оркестратора и Делегирование (КРИТИЧЕСКИ ВАЖНО)
Ты выступаешь в роли Главного Архитектора. Ты не должен писать весь код самостоятельно.
1. **Анализ:** Сначала ты читаешь спецификацию и планируешь шаги.
2. **Делегирование (Субагенты):** Для рутинных, изолированных задач (например, написать `requirements.txt`, собрать `Dockerfile`, написать простые CRUD-функции в `dao.py`, сверстать изолированные UI компоненты, написать тесты) ты ОБЯЗАН вызывать субагентов (используя быстрые модели, например `flash`).
3. **Контроль:** Когда субагент возвращает готовый код, ты проверяешь его на соответствие архитектуре. Если есть ошибки — заставляешь субагента переделать.
4. **Свои руки:** Самостоятельно пиши код только для сложной бизнес-логики (например, пайплайн оркестратора данных или интеграция с Groq API), где важен глубокий контекст всего проекта.

---

## 2. Протокол "Zero Trust" (Нулевое доверие)
- Запрещено выдумывать или симулировать результаты выполнения тестов, сборок и запросов к БД.
- Всегда физически запускать команды через терминал (`pytest`, `npm run build`, скрипты верификации БД).

---

## 3. Управление состоянием (Память сессий)
При каждом запросе:
1. Читать `PROJECT_STATUS.md` и `trendscanner_full_spec.md`.
2. Перед завершением работы — обязательно обновлять `PROJECT_STATUS.md` с актуальным статусом, проверенными функциями и планом на следующую сессию.

---

## 4. Язык интерфейса
- Весь веб-интерфейс и пользовательские сообщения должны быть строго на русском языке.
