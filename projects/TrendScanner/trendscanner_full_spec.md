## 1. Введение и концепция проекта
**TrendScanner** — это локальный, полностью автономный аналитический терминал для отслеживания, фильтрации и оценки бизнес-трендов, микрониш и способов заработка. 
Система собирает сырые данные из заданных источников, пропускает их через математические (regex/эвристика) фильтры, а затем использует LLM (Groq API) исключительно в качестве строгого классификатора для оценки потенциала и риска монетизации.

**Ключевые принципы:**
*   **Чистая архитектура и изоляция слоев:** Парсеры, ядро бизнес-логики и веб-интерфейс работают независимо.
*   **Self-hosted & Local First:** Никакой зависимости от облачных баз данных. Все данные оседают в локальной SQLite.
*   **Утилитарность GUI:** Интерфейс строится по принципу дашбордов без лишних анимаций — только сухие факты, таблицы, подсветка аномалий.

## 3. Схема базы данных (SQLite)

База данных хранится локально (например, `backend/data/trendscanner.db`).

### Таблица `sources` (Источники)
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `id` | INTEGER (PK) | Уникальный идентификатор |
| `name` | TEXT | Название (например, "Reddit /r/Entrepreneur") |
| `url` | TEXT | Прямая ссылка или API эндпоинт |
| `source_type` | TEXT | Тип парсера: `rss`, `reddit`, `telegram_html` |
| `is_active` | BOOLEAN | Включен ли источник для сканирования |
| `last_scanned`| DATETIME | Время последнего успешного сканирования |

### Таблица `trends` (Тренды)
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `id` | INTEGER (PK) | Уникальный идентификатор |
| `source_id` | INTEGER (FK)| Связь с таблицей sources |
| `original_text`| TEXT | Сырой текст поста/статьи |
| `parsed_date` | DATETIME | Время попадания в базу |
| `is_trend` | BOOLEAN | Результат первичной классификации ИИ |
| `trend_name` | TEXT | Короткое название (сгенерировано ИИ) |
| `ai_score` | INTEGER | Оценка от 1 до 10 |
| `scam_probability`| INTEGER| Процент вероятности скама (0-100) |
| `ai_summary` | TEXT | Сухая выжимка от ИИ |
| `source_url` | TEXT | Ссылка на оригинальный пост |
| `is_reviewed` | BOOLEAN | Статус "Просмотрено" пользователем |

## 4. Спецификация API (FastAPI)

Эндпоинты проектируются с учетом REST и минималистичного обмена JSON.

*   `GET /api/trends` 
    *   *Параметры:* `skip` (int), `limit` (int), `min_score` (int), `max_scam` (int), `status` (new/reviewed).
    *   *Ответ:* Список объектов трендов для грид-таблицы.
*   `PUT /api/trends/{id}/review`
    *   *Действие:* Переводит `is_reviewed` в `true`.
*   `GET /api/sources`
    *   *Ответ:* Список всех источников со статусами `is_active`.
*   `POST /api/scan/manual`
    *   *Действие:* Принудительный триггер пайплайна скрапинга и ИИ-анализа.
*   `GET /api/system/status`
    *   *Ответ:* Состояние воркеров, время следующего запуска cron, остаток лимитов Groq.

## 5. Пайплайн обработки (Оркестрация)

Процесс сбора и анализа запускается модулем `APScheduler` (раз в час) или по кнопке из GUI.

1.  **Ingestion (Сбор):** 
    Воркер запрашивает активные `sources`. В зависимости от `source_type` вызывает нужный скрипт парсинга (используются легкие `httpx` или `BeautifulSoup`).
2.  **Pre-filtering (Санитария):**
    Удаляются посты короче 100 символов, удаляются дубликаты (проверка по хешу `original_text` в БД), отрабатывает regex на спам-слова ("crypto pump", "free airdrop").
3.  **LLM Classification (Groq API):**
    Очищенные тексты (пакетами по 3-5 штук для экономии RPM) отправляются в Groq API (модель *Llama-3.1-8b-instant* или аналогичная быстрая).
    *Промпт требует JSON:* `{"is_trend": true, "trend_name": "...", "ai_score": 8, "scam_probability": 15, "ai_summary": "..."}`.
4.  **Storage:** 
    Успешно распарсенные JSON-ответы пишутся в SQLite `trends`.
