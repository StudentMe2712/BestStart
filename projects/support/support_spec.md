# 📘 Спецификация проекта: ИТС-Ком Wiki & Server Hub (BestStart)

**Версия:** 2.1.0  
**Статус:** В разработке (Спринт 1)  
**Локация:** `projects/support`  
**Стек:** Node.js 18+, Express 4.x, EJS, Vanilla CSS/JS, MariaDB (Прод Plesk) / Mock Stub (Dev)

---

## 1. Контекст и цели системы
Внутренний корпоративный портал и база знаний технических параметров серверной инфраструктуры организаций-клиентов (ИТС-Ком).
* **Пользователи:** Системные администраторы, инженеры техподдержки, 1C-специалисты.
* **Ключевой сценарий:** Быстрый поиск серверов, безопасный просмотр и копирование учетных данных (AnyDesk, RDP, SQL, 1C, iLO), ведение заметок по конфигурациям.

---

## 2. Архитектурные решения (ADR)

### ADR-001: Локальный In-Memory Mock (`db-stub.js`)
* **Контекст:** На боевом сервере Plesk база данных MariaDB доступна по порту 3306. Локально у разработчика MySQL не развернут, из-за чего сервер падал при старте.
* **Решение:** Интегрирован модуль `db-stub.js`, реализующий полный интерфейс работы с базой. При `DB_STUB=true` (скрипт `start-local.bat`) сервер работает в памяти с предзаполненными 25 организациями и локальным входом `admin / admin`.
* **Статус:** Принято.

### ADR-002: Дизайн-система Enterprise Clean & Экран входа
* **Контекст:** Предыдущий интерфейс страдал от нерационального использования экрана на разрешениях 1080p/2K и устаревших стилей.
* **Решение:** Внедрена система CSS-токенов (`style.css`), темная/светлая темы, моноширинный шрифт для реквизитов. Страница `/login` переведена на центрированную карточку 420px с маскированием пароля и показом по глазку.
* **Статус:** Принято.

### ADR-003: Командный центр (Dashboard `/`)
* **Контекст:** Главная страница состояла из двух растянутых пустых карточек с устаревшими 3D-иконками.
* **Решение:** Организован полноценный Command Hub: строка глобального поиска (`Ctrl + K`), виджеты Wiki и Событий, а также блок «Быстрый доступ» к частым серверам (ALPHUTA, Antarium, ARG, VDS) с копированием AnyDesk в 1 клик.
* **Статус:** Принято.

### ADR-004: Smart Server Viewer и маскирование учетных данных
* **Контекст:** В карточках организаций учетные записи и пароли отображались открытым текстом в одной неструктурированной простыне, что создавало риски утечки и затрудняло копирование.
* **Решение:** Внедрен компонент Smart Server Viewer, автоматически группирующий параметры в карточки: «Удаленный доступ», «Базы данных & 1C», «Железо и iLO». Пароли по умолчанию маскированы `••••••••` и оснащены кнопкой копирования в буфер обмена. Сохранен режим свободного редактирования.
* **Статус:** Принято.
