# Этап 0 — отчёт по прототипу захвата выделения (ГЕЙТ)

Прототип: `prototype/SelectCast.Prototype/` — WPF (.NET 9), одноразовый, как требует ТЗ
(«на Этапе 0 НЕ форкаем большой проект»).

## Что реализовано

- **Глобальный хоткей `Ctrl+Alt+C`** — `RegisterHotKey` + `MOD_NOREPEAT`, обработка `WM_HOTKEY`
  через `HwndSource` скрытого окна (`MainWindow.xaml.cs`).
- **Синтетический Ctrl+C** — `SendInput` (`SelectionCaptureService.SendCopyKeystroke`).
  Перед копированием **отжимаются Alt/Shift/Win**, которые пользователь физически держит в
  момент хоткея, иначе цель получает `Ctrl+Alt+C`, а не копирование.
- **Готовность буфера через `GetClipboardSequenceNumber()`** — фиксируем baseline, поллим
  каждые **15 мс** до изменения seq или таймаута **700 мс**. Читаем ровно в момент,
  когда приложение записало буфер → измеренная задержка пишется в UI/лог.
- **Буфер священен** — `ClipboardSnapshot` сохраняет **все форматы** (`GetDataObject().GetFormats(false)`),
  восстановление в блоке `finally` (восстанавливается даже при исключении). Пустой буфер →
  очищается; если снапшот не удался — буфер не трогаем (не затираем данные пользователя).
- **Fallback** — если seq не изменился за таймаут → статус «нет выделения», без падения.
  Нетекстовое изменение буфера → «нетекстовое выделение».

## Критерий GO

- [ ] Пункты 1–5 (обычные приложения) стабильно проходят.
- [ ] Пункты 7–8 (восстановление буфера) проходят, буфер не теряется.
- [ ] Пункты 9–10 (fallback) не падают.
- [ ] Замерена и зафиксирована рабочая задержка буфера (типичная _____ мс, макс _____ мс).

**GO** → переходим к Этапу 1 (форк/каркас Flow Launcher).
**NO-GO** (захват не работает в обычных приложениях 1–5 или буфер стабильно теряется) → стоп, разбор.

## Известные ограничения / на что смотреть

- **Тайминг 700 мс / 15 мс** — стартовые значения. По факту матрицы подберём минимально
  достаточные (типичная задержка обычно < 100 мс). Запиши реальные тайминги из колонки.
- **Снимок формата `false`** (только реально присутствующие форматы). Если какой-то формат не
  восстановился — он попадёт в лог («restore: skip …»); сообщи, разберём.
- **1С (п.6)** — managed-формы, поведение буфера может отличаться; по ТЗ это не блокер,
  но фиксируем результат.
- Если **п.1–2 не копируют** (приложение не успевает за хоткеем / модификаторы) — увеличить
  таймаут или добавить микропаузу перед `SendInput`; отметь в отчёте.
