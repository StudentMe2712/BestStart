# Sprint Plan — Пошаговый план разработки Second Self 1.0

**Документ:** `04_Development/Sprint_Plan.md`
**Этап:** 5. Декомпозиция разработки
**Статус:** Версия 1.0 (На согласовании)

## 1. Организация разработки и правила приемки спринтов

Разработка **Second Self 1.0** структурирована на **5 последовательных двухнедельных спринтов**.

### Правило «Done Definition» (Критерий завершения задачи)
Задача считается закрытой только при выполнении трёх условий:
1. Код написан, отформатирован и покрыт юнит/интеграционными тестами.
2. Пройден соответствующий BDD-сценарий из `03_Specification/Acceptance_Criteria.md`.
3. Потребление памяти (RAM) и отклик UI соответствуют нормативам `03_Specification/Nonfunctional_Requirements.md`.

---

## 2. Спринт 1: Инфраструктура, SQLite и Фоновая служба

* **Фокус спринта:** Создание стабильного фундамента приложения, настройка локальной БД SQLite в режиме WAL, шины событий и фонового присутствия в трее Windows.
* **Длительность:** 2 недели (10 рабочих дней).
* **Связанные документы:** `02_Technical/Architecture.md`, `02_Technical/Data_Model.md`.

### Декомпозиция задач:
* [x] **SP1-01:** Развертывание проекта WinUI 3 (Windows App SDK 1.7) + C# 14 / .NET 10 в режиме Single Project.
* [x] **SP1-02:** Настройка DI-контейнера `Microsoft.Extensions.DependencyInjection` и регистрация жизненных циклов.
* [x] **SP1-03:** Реализация движка миграций `DatabaseMigrationService` и накат схемы `001_Initial_Schema.sql`.
* [x] **SP1-04:** Реализация сервиса SQLite `SqliteConnectionFactory` с PRAGMA-настройками (`journal_mode=WAL`, `foreign_keys=ON`).
* [x] **SP1-05:** Реализация репозитория `TaskRepository` и сервиса задач `TaskService` (CRUD, сортировка).
* [x] **SP1-06:** Реализация математического движка `ProgressCalculationEngine` (формула 30/70%, ISO-8601 четверги, правило «Честные 100%»).
* [x] **SP1-07:** Реализация сервиса автоснапшотов `BackupService` (SQLite Online Backup, ротация 14 дней).
* [x] **SP1-08:** Реализация системного трея через Win32 `Shell_NotifyIconW` с контекстным меню и автозапуском реестра.
* [x] **SP1-09:** Настройка реактивной внутрипроцессной шины сообщений `WeakReferenceMessenger`.

**Проверяемый результат Спринта 1:** Приложение собирается, запускается в системный трей без окон, автоматически создаёт базу `Data/secondself.db` со всеми таблицами и триггерами, создаёт снапшот в `Backups/`, тесты математики прогресса проходят на 100%.

* **Связанные документы:** `01_UX_UI/Design_System.md`, `01_UX_UI/Widget_Specification.md`, AC-01..05.

### Декомпозиция задач:
* [x] **SP2-01:** Создание окна виджета WinUI 3 с P/Invoke стилями `WS_POPUP`, `WS_EX_TOOLWINDOW` и прозрачным фоном.
* [x] **SP2-02:** Интеграция с `IVirtualDesktopManager.PinWindow` для отображения на всех виртуальных столах Windows (`Win+Tab`).
* [x] **SP2-03:** Верстка компактного режима `360×240px` (3 стеклянные карточки с шейдерами `BackdropBlur`).
* [x] **SP2-04:** Реализация анимации раскрытия и сворачивания вниз `380×680px` на WinUI Composition (`280 мс`, кривая *Spring Out*).
* [x] **SP2-05:** Логика автосворачивания виджета при событии `Deactivated` (клик вне виджета).
* [x] **SP2-06:** Инлайн-ввод задачи дня в *Today's Focus* по кнопке `+` и глобальному шорткату `Alt+Shift+N`.

* [x] **SP2-09:** Реализация компонента `UndoToast` (5-секундное окно отмены закрытия задачи).
* [x] **SP2-10:** Реализация детектора полноэкранных игр и медиа `SystemMonitorService` (`SHQueryUserNotificationState`).

**Проверяемый результат Спринта 2:** Работающий на рабочем столе виджет в тёплом стекле, переключающийся между компактным и раскрытым видами, позволяющий мгновенно добавлять и закрывать задачи с тактильной анимацией и отменой Undo. Проходят тесты AC-01..05.

## 4. Спринт 3: Daily Reset, Видеоплеер и Ежедневный ритуал

* **Фокус спринта:** Локальная видеотека, алгоритм перемешивания без повторов, честный видеоплеер без перемотки и фиксация ритуала дня.
* **Длительность:** 2 недели (10 рабочих дней).
* **Связанные документы:** `01_UX_UI/Widget_Specification.md`, AC-06..08.

### Декомпозиция задач:
* [x] **SP3-01:** Реализация сканера локальных видеофайлов `VideoLibraryService` (`.mp4`, `.mkv`, `.webm`) и генерация кэша превью `Thumbnails/`.
* [x] **SP3-02:** Реализация алгоритма Shuffle Фишера — Йейтса без повторов (`CycleQueue`) с сохранением очереди в SQLite.
* [x] **SP3-03:** Логика смены суток в `04:00` утра: таймер суточного события, выбор нового видео и фиксация на дату.
* [x] **SP3-04:** Верстка экрана видеоплеера `Daily Reset Player` с интеграцией `MediaPlayerElement` (D3D11VA GPU Decode).
* [x] **SP3-05:** Блокировка полосы перемотки плеера (`IsHitTestVisible = false`), верстка контролов паузы и громкости.
* [x] **SP3-06:** Сервис периодического автосохранения таймкода `LastPositionMs` каждые 2 секунды в `DailyRitualLogs`.
* [x] **SP3-07:** Логика детекции конца воспроизведения (`MediaEnded`) и плавная анимация появления кнопки «Засчитать выполнение» (320 мс).
* [x] **SP3-08:** Обработчик клика «Засчитать выполнение»: запись в БД, обновление индикатора месяца и переход бейджа в `Done for Today`.
* [x] **SP3-09:** Логика тихой автозамены удалённых и повреждённых файлов видео на следующий ролик из очереди.

**Проверяемый результат Спринта 3:** Полностью функционирующий ежедневный видео-ритуал. Видео воспроизводится без перемотки с аппаратным ускорением GPU, таймкод возобновляется при закрытии, кнопка «Засчитать» начисляет дневной балл. Проходят тесты AC-06..08.

* **Связанные документы:** `01_UX_UI/Dashboard_Specification.md`, AC-09..13.

### Декомпозиция задач:
* [ ] **SP4-01:** Верстка окна Personal Dashboard `1120×780px` с темным холстом `#09090B`, Snap Layouts и навигационным Sidebar.
* [ ] **SP4-02:** Раздел **Today**: карточка активной цели недели с бейджем этапа, расширенный список задач дня и виджет Daily Reset.
* [ ] **SP4-03:** Раздел **Goals (*THE BIG PICTURE*)**: сетка до 4 Больших целей, модальное окно создания и редактирования.
* [ ] **SP4-04:** Детальный экран Большой цели: интерактивный список этапов (*Milestones*), кнопка «Завершить этап».
* [ ] **SP4-05:** Модальное окно планирования **Weekly Goal**: формулировка цели, выпадающий список этапов и фиксация (*Commitment Lock*).
* [ ] **SP4-06:** Раздел **Progress**: календарная сетка ритуалов ($28..31$ день), карточки 4/5 недель месяца и галерея архивных месяцев.

**Проверяемый результат Спринта 4:** Полноценный Personal Dashboard со всеми 5 вкладками. Связка *Большая цель → Этап → Неделя* работает без накрутки шкалы цели до закрытия этапа. Экран *Monthly Recap* запечатывает месяц. Проходят тесты AC-09..13.

## 6. Спринт 5: Стабилизация, Оптимизация производительности и Релиз

* **Фокус спринта:** Доведение производительности до стандартов NFR, стресс-тесты надёжности, устранение шероховатостей и подготовка дистрибутива.
* **Длительность:** 2 недели (10 рабочих дней).
* **Связанные документы:** `03_Specification/Nonfunctional_Requirements.md`, AC-14.

### Декомпозиция задач:
* [ ] **SP5-01:** Сквозное автоматизированное тестирование сценариев приёмки `AC-01 .. AC-14`.
* [ ] **SP5-02:** Профилирование холодного старта через WPT/ETW: оптимизация XAML-парсинга, проверка старта $\le 300\text{ мс}$.
* [ ] **SP5-03:** Профилирование памяти: проверка Working Set RAM $\le 65\text{ МБ}$ в простое и $\le 140\text{ МБ}$ при видео.
* [ ] **SP5-04:** Тестирование мультимониторности: физическое отключение мониторов, переключение разрешения и смена DPI (100%..250%).
* [ ] **SP5-05:** Стресс-тестирование базы данных: симуляция `kill -9` процесса во время записи и проверка автовосстановления из бэкапа.
* [ ] **SP5-06:** Финальная визуальная полировка: проверка контрастов WCAG, шрифтов `tnum`, скруглений и теней.
* [ ] **SP5-07:** Настройка сборки дистрибутива: подготовка автономного установщика и Portable ZIP (Self-Contained ReadyToRun).

**Проверяемый результат Спринта 5:** Готовый релиз **Second Self 1.0 (Production Release)**, соответствующий всем функциональным и нефункциональным стандартам качества.
