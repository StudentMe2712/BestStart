# Functional Requirements — Каталог функциональных требований Second Self

**Документ:** `03_Specification/Functional_Requirements.md`
**Этап:** 4. ТЗ и функциональная спецификация
**Статус:** Версия 1.0 (На согласовании)

## 1. Введение и матрица трассируемости

Настоящий документ определяет исчерпывающий перечень функциональных требований к приложению **Second Self 1.0**. Каждое требование имеет уникальный идентификатор вида `FR-XX` и строго привязано к архитектурным инвариантам проекта.

---

## 2. Модуль 1: Desktop Widget (Плавающий виджет рабочего стола)

| ID | Требование | Описание и бизнес-логика | Приоритет |
| :--- | :--- | :--- | :--- |
| **FR-01** | Двухрежимное плавающее окно | Виджет функционирует как единое окно WinUI 3 с двумя состояниями (`Compact` 360×240px и `Expanded` 380×680px) без стандартной системной рамки Windows (`WS_POPUP`). | **P0 (Must)** |
| **FR-02** | Скрытие из Alt+Tab | Окно виджета обязано иметь расширенный стиль `WS_EX_TOOLWINDOW`, исключающий его появление в диалоге переключения приложений `Alt+Tab`. | **P0 (Must)** |
| **FR-03** | Виртуальные рабочие столы | Окно виджета регистрируется через COM-интерфейс `IVirtualDesktopManager.PinWindow` и непрерывно отображается на всех виртуальных рабочих столах Windows. | **P0 (Must)** |
| **FR-04** | Закрепление поверх окон (TopMost) | Виджет поддерживает настраиваемый флаг `AlwaysOnTop`. При включении окно находится поверх остальных окон (`HWND_TOPMOST`). | **P0 (Must)** |
| **FR-05** | Автосворачивание при потере фокуса | При клике пользователя вне области виджета (событие `Window.Activated` со статусом `Deactivated`) раскрытый виджет плавно сворачивается в компактный режим (настройка включена по умолчанию). | **P1 (Should)** |
| **FR-06** | Интеллектуальное автоскрытие в Fullscreen | Фоновый сервис отслеживает статус `SHQueryUserNotificationState`. Если запущена полноэкранная игра или фильм во весь экран, виджет временно скрывается с экрана. | **P1 (Should)** |
| **FR-07** | Свободное позиционирование и мультимониторность | Пользователь может перетаскивать виджет мышью за свободное пространство карточки. Координаты нормализуются относительно `DisplayId` и сохраняются с троттлингом `500 мс`. При отключении монитора виджет автоматически центрируется на основном дисплее. | **P0 (Must)** |

## 3. Модуль 2: Управление задачами (Today's Focus & Archive)

| ID | Требование | Описание и бизнес-логика | Приоритет |
| :--- | :--- | :--- | :--- |
| **FR-08** | Быстрое создание задачи дня | Добавление задачи в *Today's Focus* по кнопке `+` или глобальному шорткату `Alt+Shift+N`. Поле инлайн-ввода принимает от 2 до 120 символов, сохранение по `Enter`, отмена по `Esc`. | **P0 (Must)** |
| **FR-09** | Трёхкнопочная панель действий задачи | При клике на задачу или кнопку `...` отображаются 3 SVG-иконки без текстовых подписей: `Выполнить`, `Редактировать инлайн`, `Удалить`. Подсказки всплывают через тултип (`300 мс`). | **P0 (Must)** |
| **FR-10** | Двухфазная анимация закрытия задачи | При нажатии «Выполнить»: 1) зачёркивание текста + чекбокс + снижение непрозрачности до 45% (350 мс); 2) схлопывание высоты строки до 0 (350 мс). Общая длительность — ровно 700 мс. | **P0 (Must)** |
| **FR-11** | Окно безопасной отмены действия (Undo) | После закрытия или удаления задачи внизу блока отображается плашка отмены на 5 секунд. Клик по «Отменить» мгновенно восстанавливает задачу в списке на прежней позиции. | **P0 (Must)** |
| **FR-12** | Автоперенос задач на следующий день | Невыполненные до `04:00` задачи автоматически остаются в списке дня. При переносе более 3 дней подряд задача помечается ненавязчивой точкой-индикатором. | **P1 (Should)** |
| **FR-13** | Изоляция задач дня от Monthly Score | Закрытие задач из *Today's Focus* учитывается в счётчиках Архива, но даёт строго **0%** в расчёт совокупного рейтинга месяца ($P$). | **P0 (Must)** |
| **FR-14** | Хроника побед (Архив выполненного) | В разделе Dashboard *Archive* отображаются сводки (*Сегодня / Эта неделя / Этот месяц*) и хронологический список всех закрытых задач с временем и датой закрытия. | **P1 (Should)** |

## 4. Модуль 3: Ежедневный ритуал (Daily Reset & Video Player)

| ID | Требование | Описание и бизнес-логика | Приоритет |
| :--- | :--- | :--- | :--- |
| **FR-15** | Локальная Shuffle-очередь видео | Система сканирует добавленные локальные видеофайлы и формирует очередь воспроизведения без повторов (алгоритм Фишера — Йейтса). Повторы роликов исключены до полного завершения цикла. | **P0 (Must)** |
| **FR-16** | Фиксация видео за логическими сутками | Ролик дня выбирается при первом старте после `04:00` утра и жёстко закрепляется за текущей датой. Перезапуск программы или перезагрузка ПК не меняют назначенное видео. | **P0 (Must)** |
| **FR-17** | Аппаратный видеоплеер без перемотки | Встроенный плеер на базе Windows Media Playback. Полоса воспроизведения отображает прогресс, но клики и перетаскивание ползунка заблокированы (`IsHitTestVisible = false`). | **P0 (Must)** |
| **FR-18** | Контроль воспроизведения (Пауза, Звук, Выход) | Пользователь может ставить видео на паузу (клик по видео/пробел), регулировать громкость/Mute и закрывать плеер в любой момент. | **P0 (Must)** |
| **FR-19** | Автосохранение позиции незавершённого просмотра | При паузе или закрытии плеера текущий таймкод `LastPositionMs` пишется в SQLite каждые 2 секунды. При повторном открытии в этот же день видео стартует с сохранённого момента. | **P0 (Must)** |
| **FR-20** | Ручная фиксация выполнения («Засчитать») | Кнопка «Засчитать выполнение» появляется только после достижения конца видео (`Position >= Duration`). Автоматический зачёт без нажатия кнопки запрещён. | **P0 (Must)** |
| **FR-21** | Лимит зачёта (1 раз в сутки) | Повторные просмотры ролика в течение дня разрешены, но в статистику ритуалов месяца ($C_D$) начисляется максимум 1 зачёт за логические сутки. | **P0 (Must)** |
| **FR-22** | Бесшовная замена битых и пропавших файлов | Если файл видео удалён или повреждён декодером, система автоматически берет следующий файл из очереди, помечает битый файл флагом `IsMissing` и уведомляет пользователя в Настройках. | **P1 (Should)** |

## 5. Модуль 4: Математика прогресса и Monthly Recap

| ID | Требование | Описание и бизнес-логика | Приоритет |
| :--- | :--- | :--- | :--- |
| **FR-23** | Формула взвешенного расчёта месяца | Ежемесячный прогресс рассчитывается строго по формуле: $P = \text{round}(W_D \times D + W_W \times W)$, где по умолчанию $W_D = 0.30$ (Daily) и $W_W = 0.70$ (Weekly). | **P0 (Must)** |
| **FR-24** | Правило «Честные 100%» | Отображение $100\%$ разрешено только при нулевом количестве пропусков ($C_D = N_D$ и $C_W = N_W$). При наличии хотя бы одного пропуска результат округления ограничивается значением `99%`. | **P0 (Must)** |
| **FR-25** | Расчёт 4 и 5 недель по стандарту ISO-8601 | Принадлежность недели к месяцу определяется по четвергу. Если четверг недели выпадает на текущий месяц, вся неделя относится к этому месяцу (в месяце строго 4 или 5 недель). | **P0 (Must)** |
| **FR-26** | Блокировка Weekly Goal (Commitment Lock) | После наступления понедельника и фиксации формулировки недельная цель блокируется от тихой подмены. Доступны только перенос, отмена с фиксацией причины или 1 замена в месяц (до среды). | **P0 (Must)** |
| **FR-27** | Пропорциональный первый месяц (Proration) | В первый месяц после установки приложения нормы $N_D$ и $N_W$ рассчитываются пропорционально количеству оставшихся дней от даты установки до конца месяца. | **P1 (Should)** |
| **FR-28** | Экран итогов месяца (Monthly Recap) | В последний вечер месяца активируется экран итогов с крупными показателями ($P$, $C_D/N_D$, $C_W/N_W$) и полем для ввода текстовой рефлексии. После подтверждения месяц становится архивным. | **P0 (Must)** |

## 6. Модуль 5: Personal Dashboard и Большие цели

| ID | Требование | Описание и бизнес-логика | Приоритет |
| :--- | :--- | :--- | :--- |
| **FR-29** | Окно Personal Dashboard | Полноразмерное окно (1120×780px) с 5 вкладками (*Today, Goals, Progress, Archive, Settings*). При клике на крестик окно скрывается в трей, не закрывая фоновый процесс. | **P0 (Must)** |
| **FR-30** | Лимит 4 активных Больших целей | Пользователь может вести одновременно не более 4 активных Больших целей. Попытка создать 5-ю цель блокируется на уровне UI и триггера SQLite. | **P0 (Must)** |
| **FR-31** | Дорожная карта этапов (Milestones) | Каждая Большая цель содержит линейный список этапов. Шкала достижения Большой цели обновляется только при явном переводе этапа в статус `Completed`. | **P0 (Must)** |
| **FR-32** | Привязка цели недели к этапу | При создании *Weekly Goal* пользователь выбирает из выпадающего списка этап активной Большой цели, формируя сквозную цепь *Цель → Этап → Неделя*. | **P0 (Must)** |
| **FR-33** | Управление видеотекой и весами в Settings | В настройках доступны: добавление видеофайлов, сканирование папок, ручной Shuffle и настройка слайдера весов прогресса ($10\%..50\%$ для Daily). | **P1 (Should)** |

## 7. Модуль 6: Системная интеграция и хранение

| ID | Требование | Описание и бизнес-логика | Приоритет |
| :--- | :--- | :--- | :--- |
| **FR-34** | Системный трей Windows | Иконка приложения в области уведомлений Windows с контекстным меню (*Открыть Dashboard, Показать/Скрыть виджет, Добавить задачу, Выход*). | **P0 (Must)** |
| **FR-35** | Автозапуск с Windows | Опция автозапуска через реестр `HKCU\...\Run` с ключом `--startup-background` для тихой фоновой инициализации виджета и трея. | **P0 (Must)** |
| **FR-36** | Ежедневное автоматическое резервное копирование | Раз в сутки в 04:00 SQLite выполняет атомарный снапшот БД в папку `Backups/` с ротацией последних 14 ежедневных копий. | **P0 (Must)** |
| **FR-37** | Самовосстановление при повреждении БД | При старте приложения выполняется проверка `PRAGMA quick_check;`. При обнаружении повреждения база автоматически восстанавливается из последнего валидного бэкапа. | **P0 (Must)** |
