## 1. Системные требования и окружение выполнения

Second Self оптимизирован для работы на современных настольных системах и ноутбуках под управлением Windows:

## 2. Работа с мониторами, DPI-масштабированием и виртуальными столами

### 2.1. DPI-масштабирование (Per-Monitor DPI Aware V2)
В манифесте приложения `app.manifest` жёстко фиксируется режим осведомлённости о масштабировании:
```xml
<application xmlns="urn:schemas-microsoft-com:asm.v3">
  <windowsSettings>
    <dpiAware xmlns="http://schemas.microsoft.com/SMI/2005/WindowsSettings">true/pm</dpiAware>
    <dpiAwareness xmlns="http://schemas.microsoft.com/SMI/2016/WindowsSettings">PerMonitorV2, PerMonitor</dpiAwareness>
  </windowsSettings>
</application>
```
* **Поведение при перетаскивании между мониторами с разным DPI (например, 100% на 24" и 150% на 4K):** окно виджета перехватывает оконное сообщение `WM_DPICHANGED`, пересчитывает масштаб через `GetDpiForWindow` и плавно адаптирует физические размеры без мыла, артефактов растеризации и сдвига координат.

### 2.2. Защита от потери окна при отключении монитора (Multi-Monitor Safety)
* Координаты виджета хранятся в `Settings/window_state.json`:
  ```json
  {
    "MonitorDevicePath": "\\\\.\\DISPLAY1",
    "MonitorResolution": { "Width": 2560, "Height": 1440 },
    "NormalizedPosition": { "X": 0.825, "Y": 0.045 },
    "IsAlwaysOnTop": true,
    "IsExpanded": false
  }
  ```
* **Алгоритм при смене дисплеев (`WM_DISPLAYCHANGE`):**
  1. Вызывается `EnumDisplayMonitors` для проверки доступности сохранённого `MonitorDevicePath`.
  2. Если монитор отключён, система находит текущий основной дисплей (`MONITORINFOF_PRIMARY`).
  3. Прямоугольник виджета позиционируется в безопасной зоне рабочего стола (`rcWork` с отступом `24px` от правого края и панели задач), исключая потерю виджета за экраном.

### 2.3. Виртуальные рабочие столы (Virtual Desktops)
* Используется интерфейс COM `IVirtualDesktopManager` (`shobjidl_core.h`).
* При запуске вызывается `PinWindow(hWnd)`, закрепляющий виджет на всех виртуальных рабочих столах. Если пользователь переключает столы клавишами `Win + Ctrl + Left/Right`, виджет мгновенно остаётся на месте без мигания и перезагрузки визуального дерева.

## 3. Видеоплеер, кодеки и контроль аппаратных ресурсов

### 3.1. Поддерживаемые форматы и кодеки
Windows Media Foundation нативно поддерживает большинство современных видеоконтейнеров:
* **Поддерживаемые контейнеры:** `.mp4`, `.m4v`, `.mov`, `.mkv`, `.webm`.
* **Поддерживаемые видеокодеки:** H.264 (AVC), H.265 (HEVC — при наличии системного расширения), VP9, AV1.
* **Аудиокодеки:** AAC, MP3, Opus, FLAC.
* **Ограничение по битрейту и разрешению:** рекомендуется видео с разрешением `1080p (1920x1080)` или `4K (3840x2160)` с частотой кадров `30/60 FPS` и аудиопотоком `44.1/48 kHz Stereo`.

### 3.2. Нулевая нагрузка на CPU и энергоэффективность
* Для рендеринга видеопотока используется Direct3D 11/12 Video Acceleration (DXVA 2.0 / D3D11VA). Декодирование полностью переносится на аппаратные блоки GPU (Intel QuickSync, NVIDIA NVDEC, AMD VCN).
* В состоянии покоя (виджет свернут, видео не воспроизводится) таймеры плеера полностью остановлены, рендеринг замирает, потребление CPU составляет **0.0%**.

## 4. Детекция полноэкранного режима (Fullscreen Games & Media)

Виджет с флагом `AlwaysOnTop` не должен мешать играм, видеоплеерам или презентациям:
* Сервис `SystemMonitorService` запускает легковесный таймер на `ThreadPool` с интервалом `1500 мс`.
* Вызывается Win32 API `SHQueryUserNotificationState(&state)`:
  * Если `state == QUNS_RUNNING_D3D_FULL_SCREEN` (запущена Direct3D игра на весь экран) $\Rightarrow$ виджет переходит в режим `Hidden` (`Visibility = Collapsed`).
  * Если активное окно в фокусе (`GetForegroundWindow`) имеет размеры, совпадающие с разрешением текущего монитора (например, YouTube или фильм в браузере на весь экран) $\Rightarrow$ виджет временно снимает флаг `HWND_TOPMOST`.
  * При возврате пользователя на рабочий стол или в обычное рабочее окно виджет автоматически и плавно восстанавливает отображение поверх окон.

## 5. Стратегия резервного копирования, миграций и целостности SQLite

### 5.1. WAL-режим и автоснапшоты (Automated Backups)
* База данных SQLite работает в режиме `WAL` (`secondself.db-wal` и `secondself.db-shm`).
* **Ежедневный фоновый бэкап:** раз в сутки в момент логической смены дня (`04:00` утра) или при первом запуске дня сервис `BackupService` вызывает нативный SQLite Online Backup API (`sqlite3_backup_init` / `Microsoft.Data.Sqlite.SqliteConnection.BackupDatabase`):
  * Снапшот сохраняется в папку `Backups/secondself_YYYYMMDD_HHMM.db.bak`.
  * Процедура бэкапа полностью атомарна и не блокирует чтение/запись данных пользователем.
  * **Ротация архивов:** система автоматически удаляет старые бэкапы, сохраняя **последние 14 ежедневных копий** (размер одного бэкапа обычно не превышает `1–5 МБ`).

### 5.2. Самовосстановление при аварийном отключении питания (Crash Recovery)
* При старте приложения выполняется быстрая диагностика `PRAGMA quick_check;`.
* Если база данных возвращает ошибку повреждения страниц (`database disk image is malformed` из-за резкого отключения питания ПК):
  1. Повреждённый файл изолируется с суффиксом `.corrupted`.
  2. Из папки `Backups/` извлекается самый свежий валидный снапшот и разворачивается как `secondself.db`.
  3. В интерфейсе виджета при запуске появляется тихое системное уведомление: *«Данные успешно восстановлены из резервной копии от [Дата]»*.

## 6. Восстановление состояния при перезапуске (State Persistence)

При внезапном закрытии процесса или перезагрузке системы пользователь не должен терять контекст:

| Состояние системы | Механизм фиксации и восстановления |
| :--- | :--- |
| **Позиция просмотра видео** | Каждые `2000 мс` воспроизведения и в событии `MediaPlayer.MediaEnded / Suspending` текущая позиция `LastPositionMs` пишется в `DailyRitualLogs`. При открытии плеера в этот же день видео стартует с `Max(0, LastPositionMs - 1000)` мс. |
| **Ввод задачи в инлайн-поле** | Если пользователь начал набирать текст задачи, но случайно свернул виджет, черновик сохраняется в оперативной памяти `DraftTaskText` и восстанавливается при следующем раскрытии. |
| **Шкала месяца (Monthly Score)** | Значения $D$, $W$ и $P$ кэшируются в памяти и синхронно пересчитываются транзакцией SQLite при каждом закрытии ритуала или недельной цели. |
| **Координаты окна виджета** | События перемещения окна (`WM_MOVE`, `WM_SIZE`) сохраняются в `window_state.json` с троттлингом в `500 мс`, исключая частую запись на диск при плавном перетаскивании мыши. |
