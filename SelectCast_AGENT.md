# SelectCast — промпт для кодинг-агента

> Это рабочий документ для AI-агента (Claude Code). Читай его целиком перед началом.
> Двигайся по этапам строго по порядку. Этап 0 — гейт: при провале НЕ продолжать.

---

## 0. Роль и правила работы

Ты — разработчик настольной утилиты для Windows на C# / .NET 9 / WPF. Ты строишь
продукт **SelectCast** как форк движка **Flow Launcher**, превращённый в собственный
продукт со своим брендом.

**Жёсткие правила на весь проект:**

1. **Этапы — последовательно.** Не перепрыгивай. Каждый этап завершается блоком
   «Критерий готовности» — пока он не выполнен, следующий этап не начинаешь.
2. **Этап 0 — это гейт.** Если прототип захвата выделения не проходит критерий —
   **остановись и доложи**. Не пиши конвертеры, бренд, настройки. Всё это бессмысленно
   без надёжного захвата.
3. **Буфер обмена священен.** Содержимое буфера пользователя ВСЕГДА восстанавливается,
   даже при исключении. Любая работа с буфером — внутри `try/finally`.
4. **Приватность.** Выделенный текст НИКОГДА не уходит в сеть. В сеть уходит только
   запрос курсов валют, и только он.
5. **Никаких лишних зависимостей.** Время, единицы, цвет — полностью офлайн, без
   внешних библиотек, где можно обойтись стандартной библиотекой .NET.
6. **После каждого этапа** — короткий отчёт: что сделано, что проверено, какие
   решения приняты, что осталось открытым.
7. **Коммить по этапам.** Один осмысленный коммит на завершённый этап.
8. **Спрашивай при развилке**, только если развилка ломает архитектуру. Мелкие
   решения принимай сам и фиксируй в отчёте.

**Технические факты, которые уже проверены (не перепроверяй):**

- Flow Launcher — open source, MIT, .NET 9, WPF. Репо: `https://github.com/Flow-Launcher/Flow.Launcher`.
- Единственный универсальный способ получить выделение из чужого приложения в Windows —
  эмуляция `Ctrl+C` через буфер обмена. «Чистого» API для чтения выделения в произвольном
  окне в Windows нет.
- API курсов валют (без ключа, разрешён кэш):
  - Основной: `fawazahmed0/exchange-api` (200+ валют, без лимитов).
  - Резерв: ExchangeRate-API open access (обновление раз в 24ч), Frankfurter (`api.frankfurter.dev`).

## 1. Что строим (суть продукта)

SelectCast: пользователь выделяет текст в **любом** приложении (Word, браузер, PDF,
мессенджер, 1С), жмёт глобальный хоткей — и в окне-лаунчере по центру экрана мгновенно
видит преобразование:

- **Валюта**: `$129` → сумма в KZT / RUB / EUR по свежему курсу (офлайн-кэш).
- **Время**: `3 PM EST` → время в Астане (UTC+5) и других целевых зонах.
- **Единицы**: `5 ft 9`, `72 °F`, `10 mi` → метрические эквиваленты.
- **Цвет**: `#3A7BD5` → плашка-превью + RGB + HSL.

Незанятый угол рынка (почему это вообще делается):
- авто-захват **уже выделенного** текста (конкуренты требуют ручного ввода в строку);
- авто-детект типа значения (не нужно выбирать режим);
- CIS-фокус: KZT/RUB и зоны Алматы/Астана/Москва, которых нет в западных аналогах.

## ЭТАП 0 — Проверка риска захвата выделения (ГЕЙТ)

**Цель:** доказать, что захват выделения и восстановление буфера работают надёжно
в реальных приложениях. Это сердце продукта. Всё остальное зависит от результата.

### Задачи

1. Создай минимальный консольный/трей-прототип (WPF или даже консоль + WinForms-трей) в
   `prototype/`. Никакого Flow Launcher здесь ещё нет.
2. Реализуй:
   - регистрацию **глобального хоткея** (например `Ctrl+Alt+C`) через Win32
     `RegisterHotKey` (или low-level keyboard hook, если так чище);
   - по хоткею: сохранить буфер → эмулировать `Ctrl+C` (`SendInput` / `keybd_event`) →
     подождать готовности буфера → прочитать текст → восстановить буфер;
   - вывод захваченного текста (в консоль/MessageBox/в окно прототипа).
3. Реализуй сохранение/восстановление буфера **аккуратно**:
   - сохраняй все доступные форматы (`Clipboard.GetDataObject()` и его форматы), не только текст;
   - восстановление оборачивай в `try/finally`, чтобы буфер вернулся даже при ошибке;
   - наивное «строку сохранил — строку вернул» НЕ подходит: теряются картинки/файлы.
4. Подбери и зафиксируй **тайминг**: задержку/поллинг готовности буфера после `Ctrl+C`
   (цель — минимально достаточная; буфер опрашивать с коротким интервалом до таймаута).
5. Сделай **fallback**: если за таймаут буфер не изменился (приложение перехватило Ctrl+C,
   выделения нет, нетекстовый контент) — прототип сообщает «нет выделения» и не падает.

### Матрица проверки (прогнать руками, записать результат в отчёт)

| # | Приложение | Сценарий | Ожидание |
|---|------------|----------|----------|
| 1 | Notepad / WordPad | выделить текст | текст захвачен |
| 2 | Microsoft Word | выделить текст | текст захвачен |
| 3 | Браузер (Chrome/Edge) | выделить текст на странице | текст захвачен |
| 4 | Просмотрщик PDF | выделить текст | текст захвачен |
| 5 | Мессенджер (Telegram/др.) | выделить сообщение | текст захвачен |
| 6 | **1С:Предприятие** | выделить текст в форме/поле | текст захвачен ИЛИ задокументирован отказ |
| 7 | Любое из выше | в буфере была СВОЯ строка до операции | строка восстановлена 1-в-1 |
| 8 | Любое из выше | в буфере было ИЗОБРАЖЕНИЕ до операции | изображение восстановлено |
| 9 | Терминал (cmd/PowerShell) | выделение / Ctrl+C перехвачен | сработал fallback, без падения |
| 10 | Пустое выделение | хоткей без выделения | fallback «нет выделения» |

> Пункт 6 (1С) — особый. Это managed-формы, поведение буфера может отличаться от обычных
> Win32-контролов. Если в 1С не работает — это НЕ повод останавливать проект, но это надо
> явно задокументировать и заложить fallback. Останавливаемся только если захват не работает
> в большинстве обычных приложений (1–5).

### Критерий готовности Этапа 0 (GO)

- Пункты 1–5 матрицы (обычные приложения) — стабильно проходят.
- Пункты 7–8 (восстановление буфера) — проходят, буфер не теряется.
- Пункты 9–10 (fallback) — не падают.
- Замерена и зафиксирована рабочая задержка буфера.

**Если GO** → отчёт + переходи к Этапу 1.
**Если NO-GO** (захват не работает в обычных приложениях или буфер стабильно теряется) →
**ОСТАНОВИСЬ**, подробно опиши, что именно не работает, какие подходы пробовал, и жди решения.

## ЭТАП 3 — Детектор типа + конвертеры «Цвет» и «Единицы» (офлайн)

Начинаем с офлайновых конвертеров — они без сети и проще всего проверяемы.

### 3.1. TypeDetector (`SelectCast.Core/Detect`)

- Вход: строка. Выход: тип (`Currency | Time | Unit | Color | Unknown`) и распарсенные данные.
- Работает по приоритетам, чтобы форматы не путались (пример: `#3A7BD5` — это цвет, а не
  «число решётка»). Цвет и единицы имеют чёткие сигнатуры — проверяй их рано.
- При неоднозначности допускается вернуть несколько кандидатов (на будущее), но для MVP —
  один лучший.
- `Unknown` → UI показывает «не удалось распознать» + ручной ввод.

### 3.2. Converter: Color (`Converters/ColorConverter`)

- Распознаёт: `#RRGGBB`, `#RGB`, `rgb(r,g,b)`, `rgba(...)`, `hsl(...)`.
- Выдаёт: HEX, RGB, HSL одновременно + данные для цветной плашки-превью.
- Каждый формат можно скопировать отдельно.

### 3.3. Converter: Units (`Converters/UnitConverter`)

- Длина: ft↔cm/m, in↔cm, mi↔km, yd↔m.
- Вес: lb↔kg, oz↔g.
- Температура: °F↔°C.
- Метрическая система — целевая по умолчанию (для CIS).
- Двунаправленность (если на входе метрическая — переводи в имперскую и наоборот).
- Поддержи составной ввод `5 ft 9` (= 5 футов 9 дюймов).

### Критерий готовности

- Юнит-тесты на детектор и оба конвертера (граничные случаи: `#FFF`, `72 °F`, `5 ft 9`,
  `10км`, мусорный ввод).
- В UI: выделил цвет → видишь плашку + 3 формата; выделил единицу → видишь пересчёт.

## ЭТАП 4 — Конвертер «Время и зоны» (офлайн)

### Задачи (`Converters/TimeConverter`)

- Распознаёт: `3 PM EST`, `15:00 UTC`, `9am PST`, `20:00 GMT+3` и похожие.
- Переводит в целевые зоны: по умолчанию **Астана (UTC+5, без DST)** + настраиваемый список
  (Москва UTC+3, UTC и т.д.).
- Учитывает DST для зон, где он есть (через `TimeZoneInfo` .NET); Астана — фиксированный +5.
- Если дата не указана — берётся текущая дата.
- Используй стандартные `TimeZoneInfo` / `DateTimeOffset` — без внешних библиотек.

### Критерий готовности

- Юнит-тесты: `3 PM EST` → корректное время в Астане и Москве; проверка зоны с DST.
- В UI: выделил время → видишь его в целевых зонах.

## ЭТАП 5 — Конвертер «Валюта» + сервис курсов (сеть + офлайн-кэш)

### 5.1. RatesService (`SelectCast.Core/Rates`)

- Источник по умолчанию: `fawazahmed0/exchange-api`. Резерв: ExchangeRate-API, Frankfurter.
- Политика: обновлять не чаще 1 раза в сутки (данные и так суточные).
- Кэш: последний успешный ответ сохраняется локально (файл в профиле пользователя).
  При отсутствии сети — использовать кэш.
- Хранить дату/время актуальности курса.
- При недоступности всех источников — отдавать кэш с флагом «возможно устарел».
- В сеть уходит ТОЛЬКО запрос курсов. Ничего из выделения.

### 5.2. CurrencyConverter (`Converters/CurrencyConverter`)

- Распознаёт: `$129`, `129 USD`, `129$`, `1 299,50 ₽`, `€1.5k` (разделители тысяч/десятичные,
  суффикс `k`).
- Целевые валюты по умолчанию: KZT, RUB, USD, EUR (настраиваемо).
- Показывает несколько целевых валют сразу.
- В выводе — дата курса (прозрачность актуальности).

### Критерий готовности

- Юнит-тесты конвертера на форматах суммы (моками курсов, без реальной сети в тестах).
- Интеграционная проверка: первый запуск с сетью кэширует курсы; отключение сети →
  конверсия по кэшу с датой; падение основного источника → переключение на резерв.
- В UI: выделил `$129` → видишь KZT/RUB/EUR + дату курса.

> Мелкие решения принимай сам и фиксируй в отчёте этапа.

## 6. Старт

1. Прочитай весь документ.
2. Начни с **Этапа 0**. Создай `prototype/`, реализуй захват, прогони матрицу, дай отчёт.
3. Жди подтверждения GO/NO-GO перед Этапом 1 — либо двигайся дальше, если отчёт по Этапу 0
   явно зелёный и тебе разрешено продолжать без паузы.
